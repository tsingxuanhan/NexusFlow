# LongHorizon-AgentBench-NF (LHAB-NF)

## 设计规格书 v0.1

*面向超长程复杂任务的群体智能评测基准*

---

## 一、设计目标

验证 NexusFlow 在以下条件下的系统能力：

1. **超长程依赖**：100+ 步原子操作，跨步骤依赖链可达 20+ 步
2. **动态不确定性**：需求变更、设备离线、工具失败、数据冲突
3. **异构约束**：端侧隐私、边侧算力受限、云端成本预算
4. **可验证恢复**：故障注入后的自动重规划、迁移、回滚
5. **质量可审计**：每一步输出带证据链，结论可追溯

---

## 二、任务类型（3 大类 × 3 难度）

### T1：跨设备个人生产力任务

模拟真实工作场景中的多设备协同。

| 难度 | 步骤数 | 设备数 | 扰动 | 隐私约束 |
|------|--------|--------|------|----------|
| Easy | 20-30 | 2 | 无 | 单设备 |
| Medium | 50-80 | 3 | 1次设备离线 + 1次需求变更 | 跨设备数据分级 |
| Hard | 100-150 | 4 | 2次离线 + 2次变更 + 1次工具失败 | 多层隐私 + 冲突约束 |

**场景示例（Hard）**：
- 手机收到邮件 → 平板读取附件 → PC 深度分析 → 云端检索公开信息 → 手机端展示含隐私数据的结果
- 注入：平板中途断网（任务迁移到 PC）、用户需求从"分析"变为"分析+对比+建议"、邮件 API 超时

### T2：长程软件工程任务

从需求到交付的完整软件工程流程。

| 难度 | 步骤数 | 代码库规模 | 扰动 | 验证方式 |
|------|--------|-----------|------|----------|
| Easy | 30-50 | 单文件 | 无 | 单元测试通过 |
| Medium | 80-120 | 多文件模块 | 1次错误注入 + 1次需求变更 | 集成测试 + 回归测试 |
| Hard | 150-200 | 跨模块系统 | 2次错误注入 + 2次变更 + 1次环境异常 | 端到端测试 + 性能回归 |

**场景示例（Hard）**：
- 理解需求文档 → 代码检索 → 设计方案 → 实现 → 测试 → 故障注入 → 修复 → 文档更新
- 注入：引入 bug 的 PR、需求描述前后矛盾、CI 环境临时不可用

### T3：数据分析与研究型任务

多源数据的发现、校验、分析和报告生成。

| 难度 | 步骤数 | 数据源数 | 扰动 | 验证方式 |
|------|--------|---------|------|----------|
| Easy | 20-30 | 2-3 | 无 | 答案正确性 |
| Medium | 50-80 | 4-6 | 1个错误数据源 + 1次冲突证据 | 证据链完整性 |
| Hard | 100-150 | 7+ | 2个错误源 + 概念混淆 + 时效性问题 | 证据链 + 结论稳健性 |

**场景示例（Hard）**：
- 多源数据发现 → 质量校验 → 假设构建 → 统计分析 → 交叉验证 → 报告生成
- 注入：含错误数据的 CSV、两份互相矛盾的文献、过时的统计口径

## 三、评估指标体系

### 3.1 核心指标（必须报告）

| 指标 | 定义 | 计算方式 |
|------|------|----------|
| **任务完成率** (TCR) | 最终交付物满足验收条件的比例 | 成功任务数 / 总任务数 |
| **步骤成功率** (SSR) | 单步原子操作成功的比例 | 成功步骤数 / 总步骤数 |
| **长程依赖恢复率** (LDRR) | 跨 10+ 步的依赖链在受到扰动后仍能正确完成的比例 | 恢复成功的依赖链数 / 被扰动的依赖链总数 |
| **目标保持率** (GHR) | 长程任务中最终输出与初始目标的一致性 | LLM 评分 (0-10) + 自动规则验证 |
| **需求变更恢复率** (RCRR) | 需求变更后系统成功重规划并完成的比例 | 成功重规划次数 / 需求变更次数 |
| **节点失效恢复率** (NFRR) | 设备/节点离线后任务成功迁移并完成的比例 | 成功迁移次数 / 离线事件次数 |
| **平均恢复时间** (ART) | 从故障/变更发生到系统恢复执行的平均时间 | Σ恢复时间 / 恢复事件数 |
| **人工干预次数** (HIC) | 需要人工介入的平均次数 | Σ干预次数 / 任务数 |

### 3.2 效率指标

| 指标 | 定义 |
|------|------|
| **Token 消耗** | 总 Token 数（含推理 + 通信） |
| **每成功任务成本** (CPS) | 总 API 费用 / 成功任务数 |
| **端到端时延** (E2E) | 从任务开始到交付完成的总时间 |
| **通信效率** (CE) | (下游质量 × 事实覆盖率) / (传输Token × (1 + 重复率 + 冲突率)) |

### 3.3 质量指标

| 指标 | 定义 |
|------|------|
| **输出质量** (OQ) | LLM 5 维评分（完整性/一致性/准确性/创新性/可操作性）|
| **错误结论率** (ECR) | 最终输出包含事实错误的比例 |
| **拒答正确率** (RAR) | 对不可回答问题的正确拒绝比例 |
| **隐私违规次数** (PVC) | 敏感数据泄露到非授权层级的次数 |
| **记忆污染率** (MPR) | 过期或错误信息被写入长期记忆的比例 |

## 五、扰动注入规范

### 5.1 扰动类型

| 类型 | 代码 | 触发条件 | 期望行为 |
|------|------|----------|----------|
| 设备离线 | `DEVICE_OFFLINE` | 任务执行中随机触发 | 任务迁移到其他设备 |
| 网络超时 | `NETWORK_TIMEOUT` | API 调用时触发 | 重试或降级 |
| 工具失败 | `TOOL_FAILURE` | 工具调用时触发 | 替代工具或手动执行 |
| 需求变更 | `REQUIREMENT_CHANGE` | 任务中途注入 | 局部重规划 |
| 数据冲突 | `DATA_CONFLICT` | 数据读取时注入 | 交叉验证后选择 |
| Agent 低质量 | `LOW_QUALITY_OUTPUT` | Agent 输出时注入 | Reviewer 拦截 |
| 记忆污染 | `MEMORY_INJECTION` | 记忆写入时触发 | 验证器拒绝 |

### 5.2 注入时机

- **Easy**: 仅在预设检查点注入，不影响关键路径
- **Medium**: 随机注入，可能影响关键路径
- **Hard**: 密集注入，多个扰动叠加，考验系统鲁棒性

## 六、评分规则

### 6.1 单任务评分

$$S_{task} = w_1 \cdot TCR + w_2 \cdot OQ_{norm} + w_3 \cdot (1 - ECR) + w_4 \cdot ART_{norm}^{-1} + w_5 \cdot (1 - PVC)$$

默认权重：$w_1=0.3, w_2=0.25, w_3=0.2, w_4=0.15, w_5=0.1$

### 6.2 配置对比评分

对方法 A 和 B：
$$\Delta_{AB} = \bar{S}_A - \bar{S}_B$$

报告 Bootstrap 95% 置信区间和配对 Wilcoxon 检验 p 值。

### 6.3 统计要求

- 每个任务类型 × 难度至少运行 **5 次**（不同随机种子）
- 报告均值 ± 标准差
- 显著性阈值：p < 0.05
